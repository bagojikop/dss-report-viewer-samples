Share a rendered report through Email, WhatsApp, or RCS/SMS. Email can use a configured delivery API or SMTP. The API regenerates the attachment using the selected report name and parameters.

Two different settings screens

Common Settings is this developer guide. Share Settings is the viewer's runtime configuration dialog, opened from its account/settings icon or from Configure sharing settings inside a Send dialog.

1. Enable Send in the Angular viewer

showSend defaults to false. The Send button appears when showSend is true and server sharing is enabled. showHeader is true here so the account/settings icon is visible; after configuration you can hide the header while keeping Send in the toolbar. Tabs support the same showSend input.

When apiUrl ends in /reports, the viewer derives the sibling /share-settings route automatically, including any deployment prefix. Supply shareSettingsUrl explicitly if your host uses a different route.

2. Configure sharing on the server

  1. Open the viewer's account/settings icon to display Share Settings.
  2. Select Enable share option in report toolbar.
  3. For each required channel, enter your delivery API URL, method, authorization mode, and any headers. For SMTP email, use the SMTP section instead.
  4. Select Save settings. The viewer saves settings through the API; it does not put service credentials in aa.config.json.

Channel endpoints can use an absolute HTTP(S) URL or a path starting with /, resolved against the API server's origin. Methods are POST, PUT, or PATCH. Authorization options are None, Bearer, Basic with an already Base64-encoded credential value, or X-Verify.

Use GET /api/share-settings to inspect public settings and PUT to save them. The example configures Email only; merge your existing channel and SMTP configuration when updating settings. Endpoint URLs and credentials are server-owned. The send controller replaces browser-supplied connection details with saved values.

SMTP uses STARTTLS, commonly on port 587, when enableSsl is true. Implicit TLS on port 465 is not supported by this implementation. SMTP takes precedence over the Email API when smtpEnabled is true. The configured server must accept the sender and recipient.

4. Send a report

  1. Open the report and set its parameters.
  2. Select Send, then Email, WhatsApp, or RCS/SMS.
  3. Enter the recipient, subject where applicable, message, and attachment format.
  4. For a configured service, select Send via API or Send via SMTP. Wait for the result before retrying.

The share attachment is rendered from the report name and parameters. The current send request does not transmit the viewer's expanded drilldown state. Screen zoom does not affect document generation.

5. Draft mode without a delivery service

When no Email API or SMTP is configured, Email opens a mailto draft. Without a WhatsApp API, WhatsApp opens a wa.me draft and requires a phone number with country code. Select Download report and attach the downloaded file manually: the browser does not automatically attach files to these drafts. RCS/SMS requires a configured API; there is no draft fallback.

The request model includes apiEndpoint, but the controller uses the endpoint, authorization, headers, and SMTP credentials from saved server settings. Changing those fields in a send request does not override saved configuration. Valid channel values are email, whatsapp, and rcs.

7. Your delivery service's contract

The reporting API exports the document, then sends this JSON to your configured delivery endpoint. Your service or adapter must accept this structure, decode the Base64 attachment, and call your messaging provider. A provider URL alone does not convert this payload into a provider-specific request.

A successful API response confirms acceptance, not final delivery to the recipient. Delivery status belongs to your provider. Redirects are not followed. If a timeout occurs, check provider status before retrying to avoid duplicates.

8. Store settings and encryption keys

Settings are encrypted in Data/share-settings.protected under the API content root by default. ShareSettingsDirectory can select another server folder. This storage path is independent of ReportDataRoot. GET responses hide tokens, header values, and SMTP passwords; blank secret fields retain saved values.

Keep the protected settings file, data-protection keys, and application name together when moving hosts or running multiple instances. Protect both settings endpoints and report delivery with your host's authentication and authorization. Credentials belong on the server, not in public aa.config.json, report-query-map.json, or report datasets.

Troubleshooting

  • Send is missing: check showSend, the server sharing toggle, and whether the share-settings GET request succeeds.
  • The settings icon is missing: set showHeader to true, or open Configure sharing settings from an available Send dialog.
  • An Email/WhatsApp draft opens: configure the service endpoint or SMTP for direct delivery.
  • RCS/SMS cannot send: configure its endpoint and adapter.
  • Delivery fails: inspect API logs, service response, saved credentials, report parameters, and SMTP configuration.

Documentation examples use reserved example domains. Automated delivery tests use local mocks; they do not send real email, WhatsApp, or SMS messages.

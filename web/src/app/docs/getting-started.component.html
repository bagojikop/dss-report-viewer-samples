One source map for all datasets. AddDssReporting registers the built-in provider in package 0.1.23+. Choose jsonFile, sqlFile, or storedProcedure per dataset in report-query-map.json. JSON needs no SQL connection. Parameters do not automatically filter JSON rows; use report filters.

CONFIGURATION / SHARED REFERENCE

Common Settings

Open Common Settings: API, Web, and .NET Core API

Web uses aa.config.json for the API address. The API uses appsettings.json for shared roots, connection strings, and CORS. All dataset source choices live in one report-query-map.json; no duplicate ReportDataFiles setting is needed.

DATA SOURCES / BUILT-IN FROM 0.1.23

JSON, SQL file, or stored procedure

Use the same Angular reportName and reportParameters for every source. AddDssReporting registers the unified provider. Set exactly one source per dataset; different datasets in one report may use different sources.

1. JSON file

Place the fixture under ReportDataRoot, then select it using jsonFile in the map. No ReportDataFiles entry, UseSqlReportData flag, or SQL connection is required.

2. SQL file

Save this query as Sql/InvoiceDetails.sql in your API. ReportSqlRoot defaults to Sql. Configure ConnectionStrings:Reporting and choose sqlFile in the map. The table shown is an example; adapt it to your schema. Query values are bound as typed parameters.

Publish SQL files with the API. For compiled SQL resources instead, set EmbeddedSqlSources to an array of resource namespace and assembly entries, such as MyApi.Sql, MyApi, and mark the SQL files as EmbeddedResource. File queries under ReportSqlRoot take precedence.

3. Stored procedure

Create the procedure in SQL Server, configure the Reporting connection string, and choose storedProcedure in the map. No loose SQL file is required for a procedure command.

Publish the map and data files

Publish JSON files, report templates, and loose SQL files used by the map. Procedures are deployed to the database. Map edits are loaded on the next request; compiled resources require rebuilding their assembly. There is no raw /datasets endpoint.

05 / DEPLOY

Publish the API and frontend

Deploy these as two applications, or serve the frontend and proxy the API under one domain. The browser must be able to reach your configured reporting endpoint.

1

Include templates and datasets

Add these rules to your API project so publish output includes your report files and JSON data.

2

Publish and host the API

Stop the development API before testing on the same port. Deploy the publish folder to a .NET 9 host, configure HTTPS, and confirm the report catalog loads. Charts, gauges, and maps in these samples require Windows hosting.

For separate domains, merge the frontend's exact origin into the API's production configuration. Use your real domain, without a trailing slash or path.

3

Build and host the Angular app

Deploy the browser output to a static web host. Configure fallback to index.html for Angular routes. When hosting under a subfolder, build with the matching --base-href, such as /reports/.

4

Set the deployed API address

Edit aa.config.json beside the deployed index.html. Replace this example domain with your API address. If the API shares the web origin, use /api/reports instead.

✓
No rebuild for API URL changes.

Save aa.config.json and reload the page. The app requests this file with caching disabled; configure your host/CDN to avoid serving a stale copy. This is public configuration, so keep credentials on the server.

Before going live

  • Confirm the deployed catalog, parameterized preview, and PDF export work with your own reports.
  • Configure application authentication, authorization, and dataset access in the API host.
  • Use HTTPS for both applications and verify the CORS origin matches the frontend.
  • Confirm direct links and refreshed Angular routes work.
